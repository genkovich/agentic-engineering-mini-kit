# Design system — agent-ops-dashboard

> Дизайн-канон проєкту. Створюється один раз через `design-system`, читається стадіями
> `ux-flows` / `screens` / `implement` / `review`. Закомічений: вибір інструмента й інвентар
> компонентів спільні для команди, а не персональні. `architecture-map.md` §Frontend лишається
> інвентарем **коду**; цей файл описує **дизайн-бік**: інструмент, платформну позицію, токени,
> інвентар компонентів і наскрізні конвенції. Оновлюй через `/sdd:design-system`, коли міняється
> фундамент.

## Platform posture

- **Posture:** responsive-both — дашборд відкривають з ноутбука поруч із терміналом, але кожен екран має один вузький варіант, щоб на телефоні чи в половині екрана нічого не ламалось.
- **Breakpoints / device classes:** один поріг `720px` (`public/style.css` (`@media (max-width: 720px)`)). Вище — таблиці й панелі в кілька колонок; нижче — одна колонка, таблиця стає списком підписаних рядків через `data-label`, навігація переносить рядок.

## Design tool

- **Tool:** code — фреймворка і збірки немає, CSP забороняє зовнішні ресурси, а команда працює з репозиторієм; тому єдине джерело правди про вигляд лежить у коді, і його видно без жодного зовнішнього інструмента.
- **Library location:** компоненти в репо це і є бібліотека: токени й класи в `public/style.css`, каркас у `views/layout.js`. Екрани нових фіч описуються markdown-вайрфреймами у `docs/features/<slug>/screens.md`; графічних макетів немає.

## Візуальний напрям

Спокійно, один акцент, дві теми. Сторінка це «бортовий журнал» роботи агента: у світлій темі прохолодний сірий фон, біла поверхня таблиці без тіней, темно-синьо-сірий текст і петроль як єдиний акцент для посилань, фокуса й активного контролу; темна тема це ті самі ролі на графітовому тлі з тим самим акцентом, посвітлішим рівно настільки, щоб тримати контраст, а не інверсія кольорів. Єдиний «гучний» елемент на будь-якому екрані — кольорова мітка проєкту: шість відтінків для шести найактивніших проєктів за рангом, решта нейтральні, тож два активні проєкти ніколи не діляться кольором. Усе інше тихе.

Чого не робимо: карток із тінями під кожним блоком, капсу в підписах, моношрифту для всього підряд (моно лише для ідентифікаторів і шляхів), градієнтів, декоративної анімації на завантаженні, 3D.

## Token source

- **Colors:** `public/style.css` (`:root`, блоки surfaces / ink / accent / status / marks / token types) — поверхні (`--bg`, `--surface`, `--surface-sunken`, `--line`, `--line-strong`), текст (`--text`, `--text-soft`, `--muted`), акцент (`--accent`, `--accent-strong`, `--accent-tint`), статуси (`--warn`, `--bad`, `--good` із тінтами), мітки проєктів (`--mark-0`…`--mark-5`), типи токенів у графіку (`--tok-out`, `--tok-in`, `--tok-cache`).
- **Dark theme:** `public/style.css` (`:root[data-theme="dark"]` і `@media (prefers-color-scheme: dark)`) — ті самі імена токенів з іншими значеннями; мітки проєктів окремо переступлені й перевірені валідатором палітри на темній поверхні. Тема іде за системою; явний вибір ставить `data-theme` на `<html>` через `public/theme.js`, який підключено в `<head>` перед стилями, щоб перший кадр уже був у правильній темі. Вибір живе лише в `localStorage` цього браузера.
- **Spacing / sizing:** `public/style.css` (`:root`, блок spacing) — шкала на 4px (`--s1`=4 … `--s7`=48), радіуси `--radius` 6px і `--radius-lg` 10px, ширина сторінки `--page-max` 1120px.
- **Typography:** `public/style.css` (`:root`, блок type) — `--font-ui` (Avenir Next → Segoe UI Variable → system-ui) для інтерфейсу, `--font-data` (SF Mono → Cascadia → ui-monospace) лише для ідентифікаторів і шляхів; розміри `--size-xs` 12 … `--size-xl` 24. Заголовок сторінки 24/600 з негативним трекінгом, тіло 15/1.5, дані в таблиці 13. Числа з `tabular-nums`. Зовнішніх шрифтів немає і не буде: CSP.

## Interaction & writing conventions

- **Errors:** page-level. Помилки читання джерела не зупиняють сторінку: показуємо, що вдалося, і додаємо `Note` з кількістю пропущеного. Стек-трейси, шляхи й тексти системних помилок на сторінку не потрапляють.
- **Empty states:** `empty()` з одним реченням, що сталося, і, якщо це допомагає перевірити налаштування, шляхом, який читали. Ілюстрацій немає.
- **Loading:** немає. Сторінка рендериться на сервері цілком, скелетонів і спінерів не буде; якщо фіча стає повільною, це питання до її специфікації, а не до індикатора.
- **Validation:** параметри запиту, які людина набирає руками, при помилці падають на типове значення з `Note`, а не на сторінку помилки.
- **Interactivity:** стан живе в URL: перемикачі й фільтри це посилання з параметрами запиту, форми надсилаються як GET. Клієнтський скрипт допускається лише як окремий файл у `public/`, підключений через `head`, і лише для того, що без нього не працює (підказки графіків); сторінка без скрипта лишається повною.
- **Motion:** лише відповідь на дію (hover, фокус), тривалість ≤120ms, під `prefers-reduced-motion`. Анімацій появи немає.
- **Microcopy tone:** англійська в інтерфейсі, речення звичайного регістру, дієслово на початку дії. Число, а не епітет: «6 sessions across 3 projects», а не «Your sessions». Мітки без капсу й без крапок-роздільників.
- **Приватність у вигляді:** сторінка показує метадані й похідні від них; текст розмови не показуємо ніколи, навіть як превʼю чи tooltip. Це не лише межа з `AGENTS.md`, а й правило дизайну: жодне поле інтерфейсу не є місцем для тіла повідомлення.
